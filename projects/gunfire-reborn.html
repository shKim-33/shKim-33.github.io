Gunfire Reborn 모작

DirectX 11 3D 수업과 병행하며, 수업 프레임워크 골격 위에 GameLogic·Editor 층과 레벨 에디터, 데이터 파이프라인, 충돌 체계를 더해 키운 개인 3D 포트폴리오입니다.

기간
2026.01 – 04 (약 3개월)
형태
개인 프로젝트
기술
C++ · DirectX 11 · HLSL · ImGui · Assimp · nlohmann-json · FMOD
AI
Codex

시연 영상

중점 구현

  • Engine → GameLogic → Client·Editor 의존 방향을 고정하고 GameInstance에 공용 API를 모아 실행 앱과 에디터가 같은 프레임워크 기능을 일관되게 사용하도록 구성
  • 레벨 전환 요청을 즉시 처리하지 않고 다음 Update 경계에서 적용하고, 충돌 처리도 LateUpdate 이후 최종 단계에 두어 순회 중 구조 변경을 피함
  • ImGui Inspector·Picking으로 Level Object를 선택·배치·수정하고, JSON 저장·복원 및 CSV→Runtime JSON 변환으로 저작 데이터와 게임 입력을 분리
  • Hitscan·Projectile·Collision Channel을 공격 방식과 대상 규칙에 맞게 적용하고, 컨테이너·파츠 구조로 몸체·약점 판정을 한 경로에 모음
  • Assimp 의존을 오프라인 변환 툴에 한정해 Model·Animation Binary를 생성하고 Runtime은 변환 완료 데이터를 읽도록 구성

AI 협업 방식

  • 프레임워크를 익히는 단계라 핵심 구조와 게임플레이는 직접 구현하고, 계획서 작성과 에디터 구축 같은 반복 작업을 AI에 맡김
  • 저장소 AGENTS.md로 작업 규칙을 고정하고, 설계 결정과 완료·폐기 계획을 문서로 관리 (완료 문서 111개·폐기 26개)

난관과 해결: 1인칭 팔 모델과 무기 모델의 애니메이션 동기화

문제

1인칭 팔과 무기가 서로 다른 Skeleton·Animation을 가지고 있어, 런타임에서 둘을 계속 맞춰야 하는 구조였습니다.

해결

런타임에서 맞추는 대신 Unity Prefab 결합·Animator 구성·FBX 내보내기와 Assimp 기반 오프라인 변환으로 문제의 경계를 제작 단계로 옮겼습니다.

결과

Runtime이 변환 완료된 단일 데이터를 재생하도록 해, 무기 전환 동작의 시각적 단절을 줄이는 기반을 마련했습니다.
