Expedition 33 모작

Clair Obscur: Expedition 33을 모작한 프로그래밍 8인 팀 프로젝트에서 이펙트를 혼자 맡아, 독립 EffectEditor부터 게임 안 전투 VFX까지 만들었습니다. EffectEditor는 팀원 4명이 실제로 사용했습니다.

기간
2026.05 – 07 (약 2개월)
형태
프로그래밍 8인 팀 프로젝트 / 이펙트 담당 1인
기술
C++ · DirectX 11 · HLSL(Compute Shader)
AI
Codex
담당
EffectEditor · 이펙트 런타임 · 메인 전투 VFX · 일부 화면 후처리 효과(흑백 연출·Flash)

시연 영상

중점 구현

  • Effect → Emitter → TypeData·Module Stack·Effect Material 계층을 독립 EffectEditor로 구성
  • Emitter·Curve·Random Distribution·Material Instance 편집과 Preview를 한 툴에서 반복 조정하도록 연결
  • EffectInstance·Runtime Desc와 Pool의 Acquire·Reset·Play를 나눠 같은 Effect Asset을 반복 재생
  • Compute Shader 상태·이력 갱신과 Instancing 출력으로 6개 Emitter 유형(Sprite·Mesh·Trail·Ribbon·Sprite Trail·Beam) 구현
  • 보간·거리 기반 재샘플링·Tangent Smoothing으로 빠른 무기·발사체의 Trail·Ribbon 품질 개선
  • Animation Notify·Socket과 Effect Asset 재생을 연결하고, Material·Emitter를 조합해 전투 VFX 제작

AI 협업 방식

  • 원작 에셋 검색·분석과 EffectEditor UI 구조 구성을 AI에 맡기고, 인스턴싱 적용 범위(Sprite 우선)와 왜곡 표현(Sprite → Mesh)은 AI 제안과 비교해 직접 결정
  • 계획서는 범위·하지 않을 것·검증 기준을 확인해 반려·승인하고, Engine 모듈·공용 API·새 패턴은 사전 승인으로 묶은 뒤 규칙이 지켜지지 않던 지점은 hook으로 차단

계획서는 반려하며 다지고, 실행은 규칙과 hook 안에서

계획서 작성 (Codex)→ 검토 · 반려 (나)→ 승인 (나)→ 구현 (Codex)→ 검증 (빌드 · 실행)→ 기록 (docs/tasks)
글로 정한 규칙이 지켜지지 않을 때

저장소 AGENTS.md에 "셰이더는 원본과 대응 파일을 먼저 읽고 수정", "데이터 테이블은 직접 고치지 않음"을 적어 두었지만 지켜지지 않는 경우가 있었습니다. 그래서 hook(.codex/hooks/pre_tool_use.py)으로 원본을 읽지 않은 셰이더 수정, 데이터 테이블 쓰기, 파괴적 git 명령을 실행 직전에 거부하게 했습니다.

계획 문서 193개(완료 179 · 폐기 14), 저장소 docs/tasks 기준 · post_project 제외

난관과 해결: EffectEditor 저작 데이터와 게임 런타임 연결

문제

Preview와 게임 결과가 달라지지 않도록 Editor와 Runtime의 데이터 형식을 하나로 맞춰야 했습니다.

해결

Engine은 EffectDefinition·EffectInstance, Editor는 Authoring·Preview, Client는 Runtime Loader를 맡도록 책임을 나눴습니다.

결과

Authoring → JSON → Runtime Loader → EffectDefinition 순서로 전달하고 Preview도 같은 EffectDefinition을 쓰게 해, Editor와 게임의 데이터 계약과 확장 시 수정 경계를 추적할 수 있게 했습니다.
