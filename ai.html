AI 협업 방식

결정은 사람이, 반복은 AI가.
그 경계를 프로젝트마다 다시 그었습니다

결정은 조작해 볼 수 있는 시안으로, 지시와 기록은 마크다운 계획서로, 실행은 단계별 위임으로, 확인은 직접 플레이와 확인 보고서로 나눴습니다. 실패한 위임은 기록해 다음 지시문과 규칙에 반영했습니다.

Destiny Overclock

실제 키보드·마우스 입력, 소리, 웹 빌드 체감은 AI 확인으로 대신하지 않고 계획서마다 "사용자 몫"으로 남겼습니다.

실패에서 바꾼 것

AI 협업에서 가장 많이 배운 건 잘 된 위임보다 실패한 위임이었습니다. Destiny Overclock에서 있었던 일입니다.

1. 자동 확인 13번을 다 통과했는데, 첫 플레이 1분 만에 화면이 고장 나 있었다

문제

2층 본 씬 구성을 서브에이전트에 13번 나눠 맡겼고, 단계마다 확인을 모두 통과했습니다. 그런데 사람이 처음 플레이하자 1분 안에 화면이 시작 지점 벽에 고정돼 보였습니다.

원인

캡처용 임시 카메라 4개가 Editor 메모리에 남아 메인 카메라를 덮고 있었습니다. 씬 파일에는 없어서 저장소만 보는 확인으로는 잡히지 않았고, 서브에이전트 보고는 모두 "삭제함"이었습니다.

바꾼 것

확인 단계에 Editor 상태(Play 종료, 임시 카메라 0개, Game 창 크기)를 넣고, 캡처는 한 장 이상 직접 열어 보며, 직접 플레이할 지점을 계획에 미리 넣었습니다. 다음 작업에서는 서브에이전트 보고에 없던 문제 2건을 직접 플레이로 잡았습니다.

2. 위임이 하나뿐인 Editor를 붙잡았다

문제

서브에이전트가 긴 Editor 스크립트와 테스트를 실행하면서 하나뿐인 Unity Editor가 응답하지 않게 됐고, 강제 종료까지 갔습니다. 위임 하나가 10~25분이라 진행 상황도 보이지 않았습니다.

바꾼 것

Editor·씬·Play 작업은 서브에이전트에 맡기지 않고 메인 세션이 체크박스 하나 단위로 짧게 직접 진행하도록 바꿨습니다. 서브에이전트는 읽기 전용 조사·코드·문서만 맡고, 계획 시작 전에 전제를 코드로 먼저 확인합니다.

3. 판정할 수 있는 것만 확인하니, 사람이 보는 것을 놓쳤다

문제

서브에이전트가 숨는 복도를 고려하지 않고 엄폐물 모양을 골랐는데, 확인 항목이 콜라이더·경로처럼 코드로 판정되는 것뿐이라 통과했습니다.

바꾼 것

"숨는 길에서 엄폐물로 읽히는가"를 플레이 시점으로 확인하는 항목을 넣고, 모델 선택은 후보를 보여 주면 제가 고르도록 했습니다.

도구를 고르는 기준

누가 몇 번 읽느냐

AI가 반복해서 읽는 계획서는 마크다운으로, 한 번 만들고 사람이 보는 시안·보고서는 공유 가능한 웹 페이지(아티팩트)로 만들었습니다. 아티팩트는 Git 밖에 있어 구현이 바뀌면 낡기 때문에, 결정의 정본은 언제나 계획서에 둡니다.

맡기기 좋은 일 / 사람이 해야 하는 일

씬 이전, 좌표표대로 배치, 프리팹 Variant, 문서 갱신처럼 확인 기준이 분명한 일은 AI 보고와 실제가 어긋난 적이 없었습니다. 반면 화면이 제대로 보이는지, 재미있는지, 길을 잃는지 같은 체감 판단과 밸런스 수치 확정은 사람이 해야 했습니다.

속도보다 "끊기지 않음"

서브에이전트 위임으로 얻은 것은 속도보다는, 메인 세션의 대화 기록이 차지 않아 긴 작업이 끊기지 않았다는 점입니다. 위임 하나에 드는 비용이 커서 아주 작은 단계는 직접 하는 편이 낫다는 것도 기록으로 확인했습니다.
